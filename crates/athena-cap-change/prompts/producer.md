## Capability: change

A focused change to this repository's code, tests, docs or configuration. Code keeps or adds tests that would fail without the change; docs match the code they describe. Build output goes to the directory Athena sets in CARGO_TARGET_DIR, outside your working directory. If criteria are about what a generated page contains, add assertions on the HTML from `cargo run -p xtask -- site` and run them before you report; a failure blocks handover (docs/conventions/rendered-page-assertions.md). When your files are under studies/ and you add or reword a statement, open each claim id it cites and check the claim text states what the sentence says, including who does the action; list each changed statement with its supporting claim text in the change description. A statement no claim supports gets a sourced claim in claims.json or is dropped, and the changelog never says claims support a wording unless they do (docs/conventions/study-claim-support.md).

For an intermittent or racy failure, first reproduce it under load with a test that loops the action on threads and counts failures (see crates/athena-testkit/tests/stand_in_stress.rs; the Bash policy denies shell loops). Name the cause in code terms; fix it where it starts. If sites share it, fix them in one shared helper and add a repo test that finds every site and fails with the cause put back. Report the command and counts before and after.

Before you report, reread the brief's criteria_check section and copy each line from it as an entry's criterion text.
