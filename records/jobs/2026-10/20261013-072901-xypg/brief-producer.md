# Job 20261013-072901-xypg: Design a requirements map, strategy view, and roadmap from BRIEF.md

## Request (verbatim)

> Requests keep landing as one-off jobs. Design a requirements map from BRIEF.md (addenda included) with status, owning design and serving jobs per requirement, plus the living strategy view (A1) and a roadmap that sequences the queued work. Design doc only.

## Reading (accepted by the user)

Write one design doc, docs/design/requirements-map.md. It maps each BRIEF.md requirement, addenda included, to a status, an owning design under docs/design/, and the jobs that serve it. It also specifies the living strategy view (A1) and a roadmap that sequences the queued work. No code changes.

Assumptions:
- 'Serving jobs' means the Athena jobs and landed commits that advanced a requirement; the doc cites them by the evidence available in the repository (CHANGELOG.md, docs/design/, docs/decisions.md), since records/ is absent.
- 'Queued work' is the set of BRIEF.md requirements with no landed design or implementation, plus any queue named in the BRIEF or docs.
- The map is a hand-maintained Markdown document with a specified update rule. No generator or checker is built, because the request says design doc only.
- The doc goes in docs/design/ in the style of existing designs.

## Acceptance criteria

1. [content] docs/design/requirements-map.md exists and has a table with one row per BRIEF.md requirement, including each addendum and A1 through A13, with columns for status, owning design doc, and serving jobs.
2. [content] Every owning design cited points to an existing file under docs/design/ or is explicitly marked 'none yet'. Every status value is defined in the doc.
3. [content] A section specifies the living strategy view for A1: its source of truth, how it is updated, and how it is kept current instead of regenerated by hand.
4. [content] A roadmap section orders the queued work with the reason for each dependency, and names what is not yet scheduled.
5. [content] The doc lists alternatives considered, cites BRIEF.md sections as sources, and labels estimates. It contains no secrets or personal data.
6. [behavior] Run `git status` and `git diff`: only Markdown files under docs/ (plus optional CHANGELOG.md) changed. No Rust, config, governance, or records/ files changed.
